Before you start: you'll need admin rights on your laptop and a stable internet connection. Everything below is free — no credit card, no paid software. Follow the steps in order and check each one off as you go.
1

Check your system is ready Windows

Windows version and virtualization support

You need Windows 10 (build 19041 or later) or Windows 11. To check your build: press Win + R, type winver, press Enter.

Then confirm virtualization is enabled — open Task Manager → Performance tab → CPU. Look for Virtualization: Enabled at the bottom right.

If it says Disabled: this needs to be turned on in your laptop's BIOS. It's usually on by default on laptops bought in the last 5 years. If yours is off, message the instructor before the session rather than during it.
2

Install WSL2 with Ubuntu Windows

One command, then a restart

Open PowerShell as Administrator (right-click the Start button → "Terminal (Admin)" or "Windows PowerShell (Admin)"), then run:

wsl --install -d Ubuntu

When it finishes, restart your laptop. After restarting, Ubuntu should open automatically — if not, search for "Ubuntu" in the Start menu.

3

Create your Ubuntu username & password Ubuntu

First launch, right after restart

The first time Ubuntu opens, it will ask you to create a username and password. This is separate from your Windows login — pick anything you'll remember, and write it down somewhere safe.

You'll land on an Ubuntu terminal prompt when this is done — that's where every step tagged Ubuntu below happens.

4

Enable systemd Ubuntu Windows

So Docker can start automatically
In Ubuntu

Open the WSL config file:

sudo nano /etc/wsl.conf

Add these two lines, then save with Ctrl+O, Enter, and exit with Ctrl+X:

[boot]
systemd=true
In Windows (PowerShell)

Shut down WSL so the change takes effect:

wsl --shutdown

Reopen Ubuntu from the Start menu. This step only needs to be done once.

5

Install Docker Engine Ubuntu

Terminal only — no Docker Desktop needed

We're installing Docker's command-line engine directly — the same way it runs on real servers. Run these one at a time inside Ubuntu:

# Set up Docker's official repository
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
# Install Docker Engine, CLI, and plugins
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
# Let Docker start automatically, and run without sudo
sudo systemctl enable docker
sudo usermod -aG docker $USER
newgrp docker

Test it:

docker run hello-world
Success looks like: a message starting with "Hello from Docker! This message shows that your installation appears to be working correctly."
6

Set up Git and GitHub Ubuntu

Account, identity, and authentication

If you don't already have a GitHub account, sign up at github.com/signup using an email you check regularly.

Then set your identity in Git so your commits are labeled correctly. Inside Ubuntu:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Next, install the GitHub CLI so pushing to GitHub doesn't ask for passwords or tokens later:

# Install GitHub CLI
(type -p wget >/dev/null || sudo apt install wget -y)
sudo mkdir -p -m 755 /etc/apt/keyrings
wget -qO- https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update
sudo apt install gh -y

Then authenticate — this is a one-time step per Ubuntu install:

gh auth login

Choose: GitHub.com → HTTPS → Yes (authenticate Git with your GitHub credentials) → Login with a web browser. It will show you a one-time code and a link — open the link, paste the code, and approve access in your browser.

Success looks like: the terminal shows "Logged in as <your-username>". You won't need to log in again after this.
7

Install VS Code + WSL extension Windows

Your editor, connected to Ubuntu
In Windows

Download VS Code from code.visualstudio.com and install it normally. Open it, go to the Extensions panel (Ctrl+Shift+X), search for WSL, and install the official Microsoft extension.

In Ubuntu

Navigate to any folder and run:

code .

VS Code should open, connected to your Ubuntu filesystem, with a terminal you can use directly inside it.

8

Final verification Ubuntu

Run these four checks before session day

Open Ubuntu and run each of these. All four should return a version number or success message, with no errors.

docker --version
Expect: Docker version 2X.X.X
docker ps
Expect: an empty table, no error
gh auth status
Expect: "Logged in as ..."
code --version
Expect: a version number, 3 lines

Troubleshooting

Task Manager shows "Virtualization: Disabled"
This needs to be enabled in your laptop's BIOS/UEFI settings (usually under an "Advanced" or "CPU Configuration" menu, look for "Virtualization Technology" or "VT-x"). If you're not comfortable doing this yourself, message the instructor before the session — don't attempt it for the first time during class.
wsl --install fails or does nothing
Make sure you're running PowerShell as Administrator (not a regular window). If it still fails, run wsl --update first, then try the install command again. A restart is often required even if not explicitly prompted.
docker ps gives a "permission denied" error
This means your user isn't in the docker group yet, or the group change hasn't taken effect. Run sudo usermod -aG docker $USER again, then fully close and reopen your Ubuntu terminal (not just newgrp docker).
docker ps says it cannot connect to the Docker daemon
The Docker service isn't running. Try sudo service docker start. If you completed Step 4 (systemd) correctly, this shouldn't happen — double check /etc/wsl.conf has the exact two lines shown above, and that you ran wsl --shutdown from PowerShell afterward.
gh auth login browser flow doesn't complete
Make sure you copy the one-time code shown in the terminal before opening the link — the browser page will ask you to paste it. If the browser opened on the wrong account, log out of GitHub in the browser first, then rerun gh auth login.
code . doesn't open VS Code from Ubuntu
Make sure the WSL extension is installed in VS Code on the Windows side first. Then close and reopen your Ubuntu terminal and try again. If it still fails, open VS Code manually and use the green "><" icon in the bottom-left corner to connect to WSL.
